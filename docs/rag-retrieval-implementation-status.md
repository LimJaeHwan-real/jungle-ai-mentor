# RAG 검색 신뢰성 구현 상태

기준: 2026-09-19, `codex/rag-grounded-reliability-implementation`의 4-B 비교 측정·6-A 로컬 검증 완료 시점. 이 문서는 [개선 계획](rag-retrieval-reliability-improvement-plan.md)의 구현·검증·미완료 항목을 구분한다. 원격 PR, 병합, 운영 배포를 완료했다는 뜻이 아니다.

## 승인된 후속 설계 — 5-D1·5-D2 로컬 구현·검증

새 질문을 `GITHUB_REPO`와 `GENERAL` 두 경로로 분류한다. GitHub 저장소 URL 또는 지정된 키워드는 저장소 경로로 보내되 URL이 없으면 주소를 요청한다. `GENERAL`은 출처 확인 표식이 있는 FAQ와 활성 내부 문서 후보를 함께 판정하고, 선택된 근거만 답변에 전달한다. 과거 출처가 불명확한 FAQ는 자동 후보에서 제외한다. 내부 근거가 부족하다고 판정된 뒤에만 웹 검색을 한 번 실행하며, 최근 후기에도 병렬 검색을 하지 않는다. 정상적으로 두 검색에서 답할 근거를 못 찾으면 LLM 생성과 저장 없이 안내한다.

아래 표는 [새 설계](superpowers/specs/2026-09-18-two-route-grounded-search-design.md)와 현재 코드의 차이를 구분한다.

## 검증 경계

- 독립 코드 검토 후 보완: GitHub API 실패나 모의 모드의 `fallback` 결과는 LLM에 전달하지 않고 실패 상태로 반환한다. URL 뒤 쉼표·마침표·한국어 조사가 붙은 유효한 저장소 주소를 인식한다. LLM 키 누락·호출 실패 때 모의 인용 답변을 반환하지 않아 `ai_questions` 저장과 FAQ 신뢰 표식을 차단한다. FAQ 검색은 조회수보다 질문 단어 일치도를 먼저 정렬한다. 수정 후 backend 전체 테스트 148개, backend·frontend 빌드, 프런트엔드 상태·렌더링 테스트 5개 통과. 새 FAQ 정렬 쿼리는 로컬 DB의 읽기 전용 트랜잭션에서 실행됐다. 인용 번호의 형식 검사는 원문의 사실 적합성을 보증하지 않는다.
- 5-D2 최신 로컬 검증: backend 전체 테스트 142개, backend·frontend 빌드, 프런트엔드 렌더링·상태 표시 테스트 5개 통과. 실제 JWT 가드와 HTTP 컨트롤러를 경유한 로컬 요청에서 미인증 401, 인증된 정상 무근거 응답 201, 내부 검색 후 웹 검색 순서·LLM 및 DB 저장 없음 확인. 이 HTTP 테스트는 검색·사용자 조회를 모의 객체로 대체했으며 실제 브라우저·OpenAI·DB를 통과한 왕복 증거는 아니다. 웹 검색 서비스는 직접 답할 근거가 없다는 명시적 결과를 버리지만, 인용된 웹페이지의 사실 적합성을 자동 보증하지는 않는다.
- 4-B 읽기 전용 확인: Docker의 로컬 PostgreSQL을 시작해 활성 내부 게시글 40건과 chunk 40개를 전수 확인했다. 예전 외부 블로그 24건·chunk 295개는 현재 검색 대상에서 제외되고, FAQ 1건은 출처 확인 표식이 없어 자동 내부 후보에서 제외된다. 사용자는 Q01~Q11을 모두 평가 질문으로 사용하기로 했고, 자료 검토 결과 Q01~Q05 `true`, Q06~Q11 `false`로 정답지를 확정했다. 재색인으로 바뀐 정답 chunk ID를 현재 DB 값으로 갱신한 뒤 아래 비교 실행으로 이어졌다.
- 4-B 비교 실행: 승인된 최대 12회 범위에서 수집을 한 번 실행하고 ID 전용 결과 11건을 평가했다. 결과 파일에는 질문·본문·답변·URL·비밀값 필드가 없음을 자동 확인했다. 기존 검색은 충분성 false 여섯 질문을 모두 충분하다고 판정했고, 개선 검색은 Q08~Q10을 근거 부족으로 바로잡았지만 Q06·Q07·Q11은 오탐으로 남았다. 관련 문서가 있는 여섯 질문의 Recall@4는 두 방식 모두 1.0이므로, 이번 개선의 주된 증거는 첫 정답 순위와 근거 부족 판정 개선이다.
- 6-A 로컬 검증: 기존 로컬 DB와 분리한 일회용 `pgvector` PostgreSQL에서 정상·실패 보존·중복 억제·재시작 복구를 확인했다. 컨테이너와 tmpfs 합성 데이터는 종료 후 삭제했다. 이후 승인된 세 질문을 OpenAI Responses `web_search`에 순차적으로 한 번씩 보냈고 재시도 없이 세 건 모두 HTTP 200·`used`로 집계됐다. 메트릭 증분은 `total=3`, `used=3`, `failed=0`, `recentDurationCount=3`, `p95DurationMs=10128`이었다. 질문·답변·URL·키는 검증 출력에 저장하지 않았다.
- 4-B·6-A 후 최종 회귀 검증: backend 26개 suite의 160개 테스트, backend build, 수집기 독립 type-check, 저장된 11건 평가 artifact의 재계산과 `git diff --check`가 통과했다. 이 검증은 로컬 브랜치 기준이며 원격 CI·배포·운영 DB 검증을 뜻하지 않는다.
- 5-D1 최신 로컬 검증: backend 전체 테스트 140개, backend·frontend 빌드, 프런트엔드 Markdown 렌더링 테스트 4개 통과. Nest 의존성 구성은 `TYPEORM_SYNC=false`와 재색인 워커 대체로 컴파일 확인했으며, 실제 앱 시작·인증 질문 왕복은 이 단계에서 실행하지 않았다. 로컬 DB의 FAQ 1건을 읽기 전용으로 집계했고 신뢰 표식이 없는 1건은 새 자동 후보 쿼리에서 제외됨을 확인했다. 프런트엔드 빌드·렌더링 검사는 제한된 실행 환경의 상위 경로 접근 오류를 피하기 위해 권한을 갖춰 재실행했다.
- 5-D1 이전 기준선: backend 테스트 121개와 backend·frontend 빌드 통과. 당시 별도 백엔드 3001 포트와 프런트엔드 5174 포트에서 HTTP 200 및 API 주소를 확인했다. 이는 새 5-D1/5-D2 브라우저 왕복 증거가 아니다.
- 새 경로의 직접 OpenAI 호출: 사용자 예시인 게임랩·게임 테크랩 최근 면접 후기 웹 검색 한 건에서 약 16.9초에 인용 7개와 두 대상 이름이 포함된 답변을 받았다. 별도 내부 근거 판정 예시 한 건은 약 1.3초에 완료됐다. 답변 내용의 정확성·최신성이나 응답 시간 분포를 이 표본으로 보장할 수 없다.
- 실제 OpenAI Responses API 호출 두 번은 모두 HTTP 200이었다. 700토큰 한도의 첫 응답은 약 12.0초에 `incomplete`, 2000토큰 한도의 다음 응답은 약 14.8초에 `completed`였다. `store: false`를 사용했고 질문·답변·URL·키는 검증 출력에 남기지 않았다. 이는 로컬 개발 환경의 단일 질문 확인이며 서비스 전체 지연 분포가 아니다.
- 이전 검증: 별도 임시 PostgreSQL에서 메타데이터·provenance 마이그레이션의 적용·되돌리기와 기존 행 보존 확인. 별도 임시 DB에서 검색 후보 및 재색인 대상 조건도 확인한 뒤 삭제했다. 기존 로컬 DB는 평가 자료 조회만 했고 스키마나 문서를 변경하지 않았다.
- 아직 검증하지 않은 범위: 실제 DB·외부 API를 포함한 인증 사용자 브라우저 왕복, 실제 OpenAI 임베딩을 이용한 전체 재색인, 운영 DB·배포·CI, 다중 인스턴스 지표와 자동 알림, 더 큰 실제 질문 평가 세트와 Q06·Q07·Q11 오탐 보완. 기존 `BLOG_SEARCH` 행과 이미 공개된 외부 자료 기반 FAQ는 삭제하지 않았다.

### 저장된 증거와 원인 분석의 한계
