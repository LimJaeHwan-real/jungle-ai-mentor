# RAG 검색 신뢰성 구현 상태

기준: 2026-09-18, 로컬 브랜치 `codex/general-adaptive-search`. 이 문서는 [개선 계획](rag-retrieval-reliability-improvement-plan.md)의 구현·검증·미완료 항목을 구분한다. 원격 PR, 병합, 운영 배포를 완료했다는 뜻이 아니다.

| 단계 | 현재 상태 | 확인된 범위와 남은 일 |
| --- | --- | --- |
| 1. 정책과 설정 | 로컬 구현·자동 테스트 통과 | production mock 차단, 실제 임베딩 설정 검사, 요청당 30초·최대 2회 재시도, 응답 차원 검사. 실제 운영 환경 검증은 미실시. |
| 2. 색인 안전성 | 로컬 구현·임시 DB 검증 통과 | 제공자·모델·차원·모드·버전·시각 메타데이터, 트랜잭션 교체, 영속 재색인 작업과 안전한 실패 코드. chunk 누락·메타데이터 불일치도 재색인 대상으로 찾는다. 별도 임시 PostgreSQL에서 마이그레이션 적용·되돌리기와 재색인 대상 조회 조건을 확인했다. 실제 대량 재색인은 미실시. |
| 3. chunk 품질 | 로컬 구현·샘플 검사 통과 | Markdown 구조·토큰 기준 분할, 섹션·원문 범위·출처·버전 저장. 기존 로컬 문서 16건을 읽기 전용으로 검사했다. 새 규칙으로 실제 문서를 재색인하는 작업은 미실시. |
| 4. 검색 품질 | 후보 결합과 근거 판정 구현, 품질 합격 판정 대기 | FTS/GIN, RRF 결합, 중복 완화와 규칙 기반 재정렬을 유지한다. `1/61` 점수 기준을 제거하고 질문의 대상·주제·시점을 내부 후보가 실제 뒷받침하는지 모델에 판정하도록 했다. 결과 ID를 검증하고 판정 실패 시 근거 답변을 중단한다. 예전 `BLOG_SEARCH` 문서·chunk는 검색과 재색인에서 제외한다. [평가 초안](rag-retrieval-evaluation-draft.md)의 Q07과 라벨은 아직 사용자 검토가 필요하며, 실제 로컬 DB 전후 결과와 개선 수치는 미측정이다. |
| 5. 답변 신뢰성 | 로컬 구현·자동 테스트 통과, 의미 검증 대기 | 신규 정글·일반 질문을 `GENERAL`로 처리하고 내부 게시글을 먼저 찾는다. 일반 질문은 근거 부족 시 질문의 대상·주제로 웹을 검색하며, 최근 후기 질문은 정상 내부 후보 조회 직후 웹 검색과 근거 판정을 겹쳐 실행한다. 인용 URL을 표시하고 외부 자료 및 이를 사용한 답변은 DB·임베딩·FAQ에 새로 저장하지 않는다. 공식 사이트 여부, 인용한 주장의 사실성, 후기 작성 시점은 자동 테스트만으로 확정하지 못한다. |
| 6. 운영 준비 | 부분 구현, 실제 검색 표본 1건 확인 | 관리자 이메일 허용 목록, 검색·임베딩·색인·웹 검색의 현재 프로세스 지표, 웹 검색 실패율과 최근 200건 p95, 읽기 전용 화면과 [점검 절차](rag-operations-runbook.md)가 있다. 실제 OpenAI 웹 검색 질문 1건은 2000토큰 한도에서 약 14.8초에 완료되고 인용 6개 중 블로그 4개를 반환했다. 이 한 건으로 평균 속도·한국어 검색 품질을 판정할 수 없다. 서버 간 영속 집계, 자동 알림 기준·통지 경로, 운영 부하 시험은 미실시다. |

## 검증 경계

- 최신 로컬 검증: backend 전체 테스트 121개와 backend·frontend 빌드 통과. 프런트엔드 빌드는 제한된 실행 환경의 파일 접근 오류 뒤 권한을 갖춰 재실행해 통과했다. 기존 실행 프로세스와 구분하기 위해 DB 스키마 동기화를 끈 새 백엔드를 3001 포트에, 새 API를 가리키는 프런트엔드를 5174 포트에 띄워 각각 HTTP 200 및 프런트엔드 API 주소를 확인했다.
- 새 경로의 직접 OpenAI 호출: 사용자 예시인 게임랩·게임 테크랩 최근 면접 후기 웹 검색 한 건에서 약 16.9초에 인용 7개와 두 대상 이름이 포함된 답변을 받았다. 별도 내부 근거 판정 예시 한 건은 약 1.3초에 완료됐다. 답변 내용의 정확성·최신성이나 응답 시간 분포를 이 표본으로 보장할 수 없다.
- 실제 OpenAI Responses API 호출 두 번은 모두 HTTP 200이었다. 700토큰 한도의 첫 응답은 약 12.0초에 `incomplete`, 2000토큰 한도의 다음 응답은 약 14.8초에 `completed`였다. `store: false`를 사용했고 질문·답변·URL·키는 검증 출력에 남기지 않았다. 이는 로컬 개발 환경의 단일 질문 확인이며 서비스 전체 지연 분포가 아니다.
- 이전 검증: 별도 임시 PostgreSQL에서 메타데이터·provenance 마이그레이션의 적용·되돌리기와 기존 행 보존 확인. 별도 임시 DB에서 검색 후보 및 재색인 대상 조건도 확인한 뒤 삭제했다. 기존 로컬 DB는 평가 자료 조회만 했고 스키마나 문서를 변경하지 않았다.
- 아직 검증하지 않은 범위: 인증된 사용자 질문의 전체 브라우저 왕복, 실제 OpenAI 임베딩을 이용한 전체 재색인, 확정 평가 세트의 품질 개선, 운영 DB·배포·CI, 다중 인스턴스 지표와 자동 알림. 기존 `BLOG_SEARCH` 행과 이미 공개된 외부 자료 기반 FAQ는 삭제하지 않았다.

## 다음 결정과 실행

1. [평가 질문 초안](rag-retrieval-evaluation-draft.md)의 Q07과 나머지 정답 자료·충분성 라벨을 현재 **내부 검색 대상만** 기준으로 검토한다. 확정 후 동일 자료의 전후 검색 결과를 [평가 도구](rag-retrieval-evaluation-input.md)로 비교한다. 합격 기준과 충분성 임계값은 측정 후 정한다.
2. 예전 `BLOG_SEARCH` 행과 이미 공개된 외부 자료 기반 FAQ의 실제 대상 수를 확인한 뒤 보존·비공개·삭제를 별도로 결정한다. 새 외부 글은 저장하지 않는다.
3. 한국어 전문 검색 처리, 외부 reranker 채택 여부, 알림 임계값·통지 경로·장기 지표 저장 방식을 별도로 결정한다.
4. 검증된 새 검색 경로와 재색인 대상을 확인한 뒤 재색인을 계획한다. 원격 PR·배포·운영 DB 변경은 아직 수행하지 않았다.
