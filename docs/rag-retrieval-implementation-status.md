# RAG 검색 신뢰성 구현 상태

기준: 2026-09-16, 로컬 브랜치 `codex/rag-embedding-timeout-retry`. 이 문서는 [개선 계획](rag-retrieval-reliability-improvement-plan.md)의 구현·검증·미완료 항목을 구분한다. 원격 PR, 병합, 운영 배포를 완료했다는 뜻이 아니다.

| 단계 | 현재 상태 | 확인된 범위와 남은 일 |
| --- | --- | --- |
| 1. 정책과 설정 | 로컬 구현·자동 테스트 통과 | production mock 차단, 실제 임베딩 설정 검사, 요청당 30초·최대 2회 재시도, 응답 차원 검사. 실제 운영 환경 검증은 미실시. |
| 2. 색인 안전성 | 로컬 구현·임시 DB 검증 통과 | 제공자·모델·차원·모드·버전·시각 메타데이터, 트랜잭션 교체, 영속 재색인 작업과 안전한 실패 코드. 별도 임시 PostgreSQL에서 마이그레이션 적용·되돌리기를 확인했다. 실제 대량 재색인은 미실시. |
| 3. chunk 품질 | 로컬 구현·샘플 검사 통과 | Markdown 구조·토큰 기준 분할, 섹션·원문 범위·출처·버전 저장. 기존 로컬 문서 16건을 읽기 전용으로 검사했다. 새 규칙으로 실제 문서를 재색인하는 작업은 미실시. |
| 4. 검색 품질 | 부분 구현, 품질 판정 대기 | FTS/GIN, RRF 결합, 중복 완화와 규칙 기반 재정렬이 있다. Recall@k·MRR·nDCG·충분성 지표 계산 도구와 질문 초안도 만들었다. 사용자 검토를 마친 정답 문서·라벨과 동일 자료의 전후 검색 결과가 없어 개선 수치는 미측정이다. 현재 `hasSufficientEvidence`의 `1/61` 기준은 RRF 첫 결과가 있으면 대체로 충족돼 검증된 충분성 기준이 아니다. |
| 5. 답변 신뢰성 | 부분 구현 | 근거 부족·검색 장애·색인 없음·외부 보강 상태를 구분하고, 근거 부족 시 LLM 답변을 건너뛴다. chunk ID·섹션·원문 범위를 답변 컨텍스트와 출처 카드에 연결하고 유효하지 않은 인용 번호를 거부한다. 번호가 문장을 실제로 뒷받침하는지의 의미 검증은 미실시다. |
| 6. 운영 준비 | 부분 구현 | 관리자 이메일 허용 목록, 검색·임베딩·색인 메모리 지표, 최근 200건 p95, 읽기 전용 화면과 [점검 절차](rag-operations-runbook.md)가 있다. 서버 간 영속 집계, 자동 알림 기준·통지 경로, 운영 부하 시험은 미실시다. |

## 검증 경계

- 최신 로컬 검증: backend 테스트 78개 통과, backend·frontend 빌드 통과.
- 이전 검증: 별도 임시 PostgreSQL에서 메타데이터·provenance 마이그레이션의 적용·되돌리기와 기존 행 보존 확인. 기존 로컬 DB는 평가 자료 조회만 했고 스키마나 문서를 변경하지 않았다.
- 아직 검증하지 않은 범위: 실제 OpenAI 임베딩을 이용한 전체 재색인, 확정 평가 세트의 품질 개선, 운영 DB·배포·CI, 다중 인스턴스 지표와 자동 알림.

## 다음 결정과 실행

1. [평가 질문 초안](rag-retrieval-evaluation-draft.md)의 정답 자료와 충분·부족·모호 라벨을 검토한다. 확정 후 실제 검색 결과를 수집해 기존 방식과 변경 후보를 [평가 도구](rag-retrieval-evaluation-input.md)로 비교한다. 합격 기준과 충분성 임계값은 측정 후 정한다.
2. 외부 블로그 허용 도메인, 이용 조건 확인, 본문 보관·삭제 정책을 결정한다. 결정 전에는 새로운 수집 범위나 저장 정책을 코드로 확정하지 않는다.
3. 한국어 전문 검색 처리, 외부 reranker 채택 여부, 알림 임계값·통지 경로·장기 지표 저장 방식을 별도로 결정한다.
4. 검증된 새 검색 경로와 재색인 대상을 확인한 뒤 재색인을 계획한다. 원격 PR·배포·운영 DB 변경은 아직 수행하지 않았다.
