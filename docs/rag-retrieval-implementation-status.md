# RAG 검색 신뢰성 구현 상태

기준: 2026-09-18, 구현 기준 커밋 `c4de6c9`. 이 문서는 [개선 계획](rag-retrieval-reliability-improvement-plan.md)의 구현·검증·미완료 항목을 구분한다. 원격 PR, 병합, 운영 배포를 완료했다는 뜻이 아니다.

## 승인된 후속 설계 — 아직 미구현

새 질문을 `GITHUB_REPO`와 `GENERAL` 두 경로로 분류한다. GitHub 저장소 URL 또는 지정된 키워드는 저장소 경로로 보내되 URL이 없으면 주소를 요청한다. 그 밖의 질문은 FAQ를 포함한 신뢰 가능한 내부 자료에서 먼저 근거를 찾고, 부족하면 웹을 한 번 검색한다. 최근 후기 검색도 내부 판정 뒤에 시작한다. 두 검색이 정상 완료됐지만 근거가 없으면 출처 없는 일반 LLM 답변 대신 자료를 찾지 못했다고 알린다. 검색 장애·활성 색인 없음·웹 API 실패는 근거 없음과 구분한다. 과거 외부 자료 기반 FAQ는 출처 확인 전까지 자동 답변 후보에서 제외하는 설계다.

이 정책은 [새 설계](superpowers/specs/2026-09-18-two-route-grounded-search-design.md)와 개선 계획에만 반영했다. 아래 표와 기존 테스트 수치는 **현재 코드**의 상태로, 새 정책의 구현·검증 결과가 아니다.

## 검증 경계

- 최신 로컬 검증: backend 전체 테스트 121개와 backend·frontend 빌드 통과. 프런트엔드 빌드는 제한된 실행 환경의 파일 접근 오류 뒤 권한을 갖춰 재실행해 통과했다. 기존 실행 프로세스와 구분하기 위해 DB 스키마 동기화를 끈 새 백엔드를 3001 포트에, 새 API를 가리키는 프런트엔드를 5174 포트에 띄워 각각 HTTP 200 및 프런트엔드 API 주소를 확인했다.
- 새 경로의 직접 OpenAI 호출: 사용자 예시인 게임랩·게임 테크랩 최근 면접 후기 웹 검색 한 건에서 약 16.9초에 인용 7개와 두 대상 이름이 포함된 답변을 받았다. 별도 내부 근거 판정 예시 한 건은 약 1.3초에 완료됐다. 답변 내용의 정확성·최신성이나 응답 시간 분포를 이 표본으로 보장할 수 없다.
- 실제 OpenAI Responses API 호출 두 번은 모두 HTTP 200이었다. 700토큰 한도의 첫 응답은 약 12.0초에 `incomplete`, 2000토큰 한도의 다음 응답은 약 14.8초에 `completed`였다. `store: false`를 사용했고 질문·답변·URL·키는 검증 출력에 남기지 않았다. 이는 로컬 개발 환경의 단일 질문 확인이며 서비스 전체 지연 분포가 아니다.
- 이전 검증: 별도 임시 PostgreSQL에서 메타데이터·provenance 마이그레이션의 적용·되돌리기와 기존 행 보존 확인. 별도 임시 DB에서 검색 후보 및 재색인 대상 조건도 확인한 뒤 삭제했다. 기존 로컬 DB는 평가 자료 조회만 했고 스키마나 문서를 변경하지 않았다.
- 아직 검증하지 않은 범위: 인증된 사용자 질문의 전체 브라우저 왕복, 실제 OpenAI 임베딩을 이용한 전체 재색인, 확정 평가 세트의 품질 개선, 운영 DB·배포·CI, 다중 인스턴스 지표와 자동 알림. 기존 `BLOG_SEARCH` 행과 이미 공개된 외부 자료 기반 FAQ는 삭제하지 않았다.

## 다음 결정과 실행

1. 두 경로와 신뢰 가능한 FAQ 후보 검색을 구현·검증한다. 다음으로 내부 판정 후 웹 검색과 근거 없음 안내를 구현·검증한다. 코드 변경은 이번 문서 작업에 포함하지 않는다.
2. [평가 질문 초안](rag-retrieval-evaluation-draft.md)의 Q07과 나머지 정답 자료·충분성 라벨을 현재 **내부 검색 대상만** 기준으로 검토한다. 확정 후 동일 자료의 전후 검색 결과를 [평가 도구](rag-retrieval-evaluation-input.md)로 비교한다. 합격 기준과 충분성 임계값은 측정 후 정한다.
3. 예전 `BLOG_SEARCH` 행과 이미 공개된 외부 자료 기반 FAQ의 실제 대상 수를 확인한 뒤 보존·비공개·삭제를 별도로 결정한다. 새 외부 글은 저장하지 않는다.
4. 한국어 전문 검색 처리, 외부 reranker 채택 여부, 알림 임계값·통지 경로·장기 지표 저장 방식을 별도로 결정한다.
5. 검증된 새 검색 경로와 재색인 대상을 확인한 뒤 재색인을 계획한다. 원격 PR·배포·운영 DB 변경은 아직 수행하지 않았다.
