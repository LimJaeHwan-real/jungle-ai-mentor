# RAG 검색 신뢰성 구현 상태

기준: 2026-09-18, `codex/rag-grounded-reliability-implementation`의 5-D2 로컬 검증 시점. 이 문서는 [개선 계획](rag-retrieval-reliability-improvement-plan.md)의 구현·검증·미완료 항목을 구분한다. 원격 PR, 병합, 운영 배포를 완료했다는 뜻이 아니다.

## 승인된 후속 설계 — 5-D1·5-D2 로컬 구현·검증

새 질문을 `GITHUB_REPO`와 `GENERAL` 두 경로로 분류한다. GitHub 저장소 URL 또는 지정된 키워드는 저장소 경로로 보내되 URL이 없으면 주소를 요청한다. `GENERAL`은 출처 확인 표식이 있는 FAQ와 활성 내부 문서 후보를 함께 판정하고, 선택된 근거만 답변에 전달한다. 과거 출처가 불명확한 FAQ는 자동 후보에서 제외한다. 내부 근거가 부족하다고 판정된 뒤에만 웹 검색을 한 번 실행하며, 최근 후기에도 병렬 검색을 하지 않는다. 정상적으로 두 검색에서 답할 근거를 못 찾으면 LLM 생성과 저장 없이 안내한다.

아래 표는 [새 설계](superpowers/specs/2026-09-18-two-route-grounded-search-design.md)와 현재 코드의 차이를 구분한다.

| 단계 | 현재 상태 | 확인된 범위와 남은 일 |
| --- | --- | --- |
| 1. 정책과 설정 | 로컬 구현·자동 테스트 통과 | production mock 차단, 실제 임베딩 설정 검사, 요청당 30초·최대 2회 재시도, 응답 차원 검사. 실제 운영 환경 검증은 미실시. |
| 2. 색인 안전성 | 로컬 구현·임시 DB 검증 통과 | 제공자·모델·차원·모드·버전·시각 메타데이터, 트랜잭션 교체, 영속 재색인 작업과 안전한 실패 코드. chunk 누락·메타데이터 불일치도 재색인 대상으로 찾는다. 별도 임시 PostgreSQL에서 마이그레이션 적용·되돌리기와 재색인 대상 조회 조건을 확인했다. 실제 대량 재색인은 미실시. |
| 3. chunk 품질 | 로컬 구현·샘플 검사 통과 | Markdown 구조·토큰 기준 분할, 섹션·원문 범위·출처·버전 저장. 기존 로컬 문서 16건을 읽기 전용으로 검사했다. 새 규칙으로 실제 문서를 재색인하는 작업은 미실시. |
| 4. 검색 품질 | 후보 결합과 근거 판정 구현, 4-B 라벨 확정 대기 | FTS/GIN, RRF 결합, 중복 완화와 규칙 기반 재정렬을 유지한다. `1/61` 점수 기준을 제거하고 질문의 대상·주제·시점을 내부 후보가 실제 뒷받침하는지 모델에 판정하도록 했다. 결과 ID를 검증하고 판정 실패 시 근거 답변을 중단한다. 예전 `BLOG_SEARCH` 문서·chunk는 검색과 재색인에서 제외한다. [평가 초안](rag-retrieval-evaluation-draft.md)의 Q07은 내부 게시글 재검토 뒤 `false`를 제안했으나 사용자 확정이 필요하다. 실제 동일 자료 전후 결과와 개선 수치는 미측정이다. |
| 5. 답변 신뢰성 | 5-D1·5-D2 로컬 검증 통과 | 새 질문 경로는 두 가지로 제한하고 URL 없는 GitHub 키워드에는 주소를 요청한다. 출처 확인 표식이 있는 FAQ와 게시글 중 판정이 고른 것만 LLM에 전달한다. 내부 근거 부족 뒤 웹 검색을 한 번 실행하고, 정상 무근거·내부 장애·활성 색인 없음·웹 장애·인용 실패를 별도 답변 상태로 표시한다. 외부 답변과 근거 없는 안내는 저장하지 않는다. 실제 검색 품질·인용 사실성은 미검증이다. |
| 6. 운영 준비 | 부분 구현, 6-A 로컬 읽기 전용 확인 | 관리자 이메일 허용 목록, 검색·임베딩·색인·웹 검색의 현재 프로세스 지표, 웹 검색 실패율과 최근 200건 p95, 읽기 전용 화면과 [점검 절차](rag-operations-runbook.md)가 있다. 이전 실제 OpenAI 웹 검색 질문 1건은 약 14.8초에 완료됐다. 현재 로컬 DB의 재색인 작업·항목은 0건이며 앱 프로세스가 없어 웹 지표 표본은 읽지 못했다. 서버 간 영속 집계, 자동 알림 기준·통지 경로, 운영 부하 시험은 미실시다. |

## 검증 경계

- 5-D2 최신 로컬 검증: backend 전체 테스트 142개, backend·frontend 빌드, 프런트엔드 렌더링·상태 표시 테스트 5개 통과. 실제 JWT 가드와 HTTP 컨트롤러를 경유한 로컬 요청에서 미인증 401, 인증된 정상 무근거 응답 201, 내부 검색 후 웹 검색 순서·LLM 및 DB 저장 없음 확인. 이 HTTP 테스트는 검색·사용자 조회를 모의 객체로 대체했으며 실제 브라우저·OpenAI·DB를 통과한 왕복 증거는 아니다. 웹 검색 서비스는 직접 답할 근거가 없다는 명시적 결과를 버리지만, 인용된 웹페이지의 사실 적합성을 자동 보증하지는 않는다.
- 4-B 읽기 전용 확인: 로컬 활성 내부 게시글 40건에서 Q07과 관련된 게시글 1건을 찾았지만, 그 글은 다른 후기의 교훈 요약일 뿐 1기 수료자의 1년 뒤 직접 경험은 아니다. 초안의 9개 문서 식별자는 모두 현존하며 예전 외부 블로그 1건만 현재 내부 검색 대상에서 제외된다. `false` 라벨을 제안했으며 사용자 확정과 동일 자료 전후 검색 측정은 대기 중이다.
- 6-A 읽기 전용 확인: 로컬 재색인 작업과 항목은 0건, 활성 내부 게시글 색인은 40건, 검색에서 제외된 과거 외부 블로그 색인은 24건이었다. 앱 프로세스가 없어 현재 프로세스 웹 검색 지표를 읽지 못했고, 별도 검증 환경이나 실제 외부 호출은 실행하지 않았다.
- 5-D1 최신 로컬 검증: backend 전체 테스트 140개, backend·frontend 빌드, 프런트엔드 Markdown 렌더링 테스트 4개 통과. Nest 의존성 구성은 `TYPEORM_SYNC=false`와 재색인 워커 대체로 컴파일 확인했으며, 실제 앱 시작·인증 질문 왕복은 이 단계에서 실행하지 않았다. 로컬 DB의 FAQ 1건을 읽기 전용으로 집계했고 신뢰 표식이 없는 1건은 새 자동 후보 쿼리에서 제외됨을 확인했다. 프런트엔드 빌드·렌더링 검사는 제한된 실행 환경의 상위 경로 접근 오류를 피하기 위해 권한을 갖춰 재실행했다.
- 5-D1 이전 기준선: backend 테스트 121개와 backend·frontend 빌드 통과. 당시 별도 백엔드 3001 포트와 프런트엔드 5174 포트에서 HTTP 200 및 API 주소를 확인했다. 이는 새 5-D1/5-D2 브라우저 왕복 증거가 아니다.
- 새 경로의 직접 OpenAI 호출: 사용자 예시인 게임랩·게임 테크랩 최근 면접 후기 웹 검색 한 건에서 약 16.9초에 인용 7개와 두 대상 이름이 포함된 답변을 받았다. 별도 내부 근거 판정 예시 한 건은 약 1.3초에 완료됐다. 답변 내용의 정확성·최신성이나 응답 시간 분포를 이 표본으로 보장할 수 없다.
- 실제 OpenAI Responses API 호출 두 번은 모두 HTTP 200이었다. 700토큰 한도의 첫 응답은 약 12.0초에 `incomplete`, 2000토큰 한도의 다음 응답은 약 14.8초에 `completed`였다. `store: false`를 사용했고 질문·답변·URL·키는 검증 출력에 남기지 않았다. 이는 로컬 개발 환경의 단일 질문 확인이며 서비스 전체 지연 분포가 아니다.
- 이전 검증: 별도 임시 PostgreSQL에서 메타데이터·provenance 마이그레이션의 적용·되돌리기와 기존 행 보존 확인. 별도 임시 DB에서 검색 후보 및 재색인 대상 조건도 확인한 뒤 삭제했다. 기존 로컬 DB는 평가 자료 조회만 했고 스키마나 문서를 변경하지 않았다.
- 아직 검증하지 않은 범위: 실제 DB·외부 API를 포함한 인증 사용자 브라우저 왕복, 실제 OpenAI 임베딩을 이용한 전체 재색인, 확정 평가 세트의 품질 개선, 운영 DB·배포·CI, 다중 인스턴스 지표와 자동 알림. 기존 `BLOG_SEARCH` 행과 이미 공개된 외부 자료 기반 FAQ는 삭제하지 않았다.

## 다음 결정과 실행

1. [평가 질문 초안](rag-retrieval-evaluation-draft.md)의 Q07과 나머지 정답 자료·충분성 라벨을 현재 **내부 검색 대상만** 기준으로 검토한다. 확정 후 동일 자료의 전후 검색 결과를 [평가 도구](rag-retrieval-evaluation-input.md)로 비교한다. 합격 기준과 충분성 임계값은 측정 후 정한다.
2. 예전 `BLOG_SEARCH` 행과 이미 공개된 외부 자료 기반 FAQ의 실제 대상 수를 확인한 뒤 보존·비공개·삭제를 별도로 결정한다. 새 외부 글은 저장하지 않는다.
3. 한국어 전문 검색 처리, 외부 reranker 채택 여부, 알림 임계값·통지 경로·장기 지표 저장 방식을 별도로 결정한다.
4. 검증된 새 검색 경로와 재색인 대상을 확인한 뒤 재색인을 계획한다. 원격 PR·배포·운영 DB 변경은 아직 수행하지 않았다.
