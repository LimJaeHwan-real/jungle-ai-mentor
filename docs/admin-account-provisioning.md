# 관리자 계정 생성 절차

관리자 이메일은 일반 회원가입에서 예약 주소로 취급해 거부한다. 실제 계정 생성은 서버 접근 권한을 가진 운영자가 `backend`의 `npm.cmd run admin:create`로만 진행한다. 웹 계정 생성 API를 추가하지 않는다. 이 변경은 기존 계정의 소유권을 검증하거나 기존 허용 계정을 자동으로 안전하게 만들지 않는다.

## 최초 설정과 기존 계정 확인

1. 관리 API가 외부에 노출되지 않은 유지보수 상태에서 새 코드를 배포한다. 구버전 회원가입 서버가 남아 있으면 먼저 종료한다. 모든 인스턴스의 허용 목록을 동일하게 적용한다.
2. 기존 DB에 사용할 이메일의 계정이 있는지 운영자가 읽기 전용으로 확인한다. 이미 있으면 자동 승격·삭제·비밀번호 재설정을 하지 않는다. 본인이 만든 계정인지 확인되지 않으면 허용 목록에 넣지 않는다. 필요하면 새 전용 이메일을 선택한다. 기존 일반 계정의 비밀번호 재설정만으로 소유권이 증명되는 것은 아니다.
3. 로컬 비공개 설정에 `ADMIN_EMAIL_ALLOWLIST`와 대상 DB 설정을 입력한다. 값은 Git·문서·채팅·로그에 남기지 않는다. `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`이 모두 명시돼야 생성 명령이 실행된다. 설정 우선순위는 서버와 동일하게 프로세스 환경, `.env.local`, `.env`다.
4. 해당 목록을 적용한 모든 서버에서 예약 이메일의 공개 가입이 차단되는지 확인한다. 설정 변경은 이미 실행 중인 서버에 자동 적용되지 않는다. 계정 생성·로그인 검증이 끝날 때까지 유지보수 상태를 유지한다.

## 운영자 전용 생성

`backend`에서 `npm.cmd run admin:create`를 인자 없이 실행한다. 대화형 터미널만 허용하며 이메일·닉네임·비밀번호는 입력 중 표시하지 않는다. 비밀번호는 12자 이상, UTF-8 기준 72바이트 이하로 입력하고 다시 확인한다. DB 대상을 직접 확인한 후 마지막 입력에 `CREATE`를 입력해야 생성한다. 취소는 Ctrl+C다.

- 허용 목록의 이메일만 생성한다. 기존 계정이 있으면 중단하며 덮어쓰지 않는다. 동시 생성은 DB의 이메일 unique 제약으로 중복을 거부한다.
- 비밀번호는 bcrypt 해시로만 저장한다. 명령 인자·환경 변수·출력에 비밀번호를 넣지 않는다. 이 명령은 로그인 토큰을 발급하지 않는다.
- DB 스키마 동기화, 마이그레이션, extension 자동 설치를 끈다. 계정 생성 외의 데이터 변경을 수행하지 않는다.
- 실패 시 비밀값이나 SQL 상세를 출력하지 않는다. 연결 종료 중 오류가 나면 생성이 이미 완료됐을 수도 있으므로 무조건 재실행하지 말고 존재 여부를 확인한다.

## 확인과 운영

생성 후 일반 로그인으로 관리자 화면과 관리자 API 접근을 확인하고 일반 계정은 403, 미인증 요청은 401인지 확인한다. 실제 계정 생성·설정 변경·서버 재시작은 각각 승인된 운영 환경에서만 수행한다. 자동 테스트 통과는 실제 계정 생성 완료를 뜻하지 않는다.

허용 목록에서 이메일을 제거하면 해당 설정을 적용한 서버의 관리자 권한이 사라진다. 계정을 삭제하거나 비밀번호를 바꾸지는 않는다. 새 관리자를 추가할 때도 기존 계정 소유 확인부터 반복한다. 이 최소 보완은 이메일 인증 서비스를 도입하는 변경이 아니며, 운영자가 허용 목록과 기존 계정의 신뢰성을 관리할 책임은 남는다.
