# 두 경로와 근거 기반 답변 설계

상태: 2026-09-18 승인된 **구현 목표**. 이 문서는 현재 코드의 동작이나 검증 완료를 뜻하지 않는다. 기존 [GENERAL 적응형 검색 설계](2026-09-18-general-adaptive-search-design.md)는 이전 구현 기록으로 보존한다.

## 사용자 흐름

1. 새 질문은 `GITHUB_REPO` 또는 `GENERAL`로만 분류한다.
2. 유효한 GitHub 저장소 URL이 있거나 질문에 독립된 `github`·`repo`·`repository` 토큰 또는 `깃허브`가 있으면 `GITHUB_REPO`다. 분석할 URL이 없으면 주소를 요청하며, 일반 문장을 저장소 URL인 것처럼 분석하지 않는다. 따라서 “깃허브로 공부하는 법”도 이 명시적 키워드 규칙에 따라 주소 요청으로 이어질 수 있다.
3. 나머지 `GENERAL` 질문은 신뢰 가능한 공개 FAQ와 활성 내부 게시글·문서에서 후보를 찾는다. FAQ라는 단어를 사용자가 말할 필요는 없다. 후보가 질문의 대상·주제·시점을 직접 뒷받침하는지 판정하고, 충분하면 그 출처만 사용해 답한다.
4. 내부 검색과 근거 판정이 정상 완료됐지만 부족하면 질문의 실제 대상·주제·시점으로 웹을 한 번 검색한다. 최근 후기에도 동일한 순서를 적용하며 병렬 웹 검색은 제거한다. 인용 가능한 관련 근거가 있으면 출처 링크와 함께 답한다.
5. 내부와 웹 검색이 모두 정상 완료됐으나 사용할 근거가 없으면 “현재 연결된 내부 자료와 웹 검색에서 질문에 답할 만한 근거를 찾지 못했습니다. 질문을 더 구체적으로 적거나 참고할 링크를 알려주세요.”라고 안내한다. 출처 없는 일반 LLM 답변은 생성하지 않는다. 이 안내는 세상에 자료가 전혀 없다는 단정이 아니다.

## 검색과 신뢰 경계

- 질문 경로(`GITHUB_REPO`/`GENERAL`)와 `GENERAL` 내부의 검색 의도(최근 후기·후기·공식 사실·일반 지식)는 별개다. 검색 의도는 웹 검색 지시문에만 사용하며 추가 질문 경로를 만들지 않는다.
- FAQ는 `faqs`의 공개 질문·답변을 내부 후보로 취급한다. 현재 질문 문장 전체의 `ILIKE` 포함 검사만으로는 표현이 다른 FAQ를 놓치므로 후보 검색을 개선하고, 게시글과 마찬가지로 근거 충분성을 판정한다. FAQ 제목·질문·답변과 식별자를 참고 근거에 연결한다.
- 과거 외부 블로그·GitHub 자료가 섞였거나 출처를 확인할 수 없는 FAQ는 자동 답변 후보에 넣지 않는다. 기존 FAQ 행을 변경·삭제하지 않고 먼저 출처와 `ai_questions.usedTools` 등 현재 기록을 조사한다. 실제 후보 허용 조건은 이 조사 결과로 검증한다.
- GitHub URL은 실제 `github.com/<owner>/<repo>` 형태인지 확인한다. 키워드만 있는 질문에서 URL을 만들어내지 않는다. 이 경로의 외부 자료와 분석 답변은 기존 미저장 정책을 따른다.
- 내부 근거 판정은 후보의 검색 점수만으로 충분하다고 하지 않는다. 답변 생성 LLM에는 확인된 근거만 전달하고 인용 번호·URL 연결을 검증한다. `LlmService.answer`를 빈 근거로 호출해 일반 지식이나 mock 답변을 만드는 경로를 막는다.
- 웹 검색은 20초 제한·자동 재시도 없음·`store: false`를 유지한다. 검색의 정상 완료와 인용 가능한 근거의 부재를 API 실패와 구분한다. 외부 원문·발췌·GitHub README와 외부 자료를 사용한 답변은 애플리케이션 DB·FAQ·임베딩에 저장하지 않는다.

## 결과와 실패 처리

| 상태 | 사용자에게 표시할 내용 | 웹 검색 | 출처 없는 답변 |
| --- | --- | --- | --- |
| 내부 근거 충분 | 내부 FAQ·게시글의 확인된 답변과 출처 | 실행하지 않음 | 만들지 않음 |
| 내부 근거 부족 | 웹에서 질문에 맞는 인용 근거 탐색 | 한 번 실행 | 만들지 않음 |
| 두 검색 정상, 사용 가능한 근거 없음 | 현재 연결된 자료에서 근거를 찾지 못했다는 안내 | 완료 | 만들지 않음 |
| 내부 검색 장애·활성 색인 없음 | 재시도 또는 운영자 재색인 안내 | 실행하지 않음 | 만들지 않음 |
| 웹 API 실패·시간 초과 | 내부 근거 부족과 외부 검색 실패를 함께 알림 | 실패 상태 유지 | 만들지 않음 |
| GitHub 키워드만 있고 저장소 URL 없음 | 분석할 GitHub 저장소 URL 요청 | 실행하지 않음 | 만들지 않음 |

## 호환성과 구현 단위

- `AiQuestion.agentRoute`의 과거 `FAQ_SEARCH`·`JUNGLE_KNOWLEDGE` 값과 enum은 기록 호환성을 위해 보존한다. 새 질문은 두 경로만 사용한다. 이 설계만으로 DB 마이그레이션이나 기존 데이터 변경은 필요하지 않다.
- 1단위: 질문 분류, URL 없는 GitHub 안내, 신뢰 가능한 FAQ 후보 검색과 내부 근거 판정. 라우트·FAQ 표현 차이·출처 경계·모듈 시작을 검증한다.
- 2단위: 내부 판정 뒤 순차 웹 검색, 정상 무근거 안내, 장애별 메시지와 출처 없는 LLM 호출 차단. 단위 테스트·백엔드 빌드·인증된 로컬 질문 전체 흐름을 검증한다.
- 최근 후기 질문은 기존 병렬 방식보다 응답이 늦을 수 있다. 실제 지연·검색 품질·근거 충분성은 사용자 검토를 마친 평가 질문과 로컬 측정으로 확인한다.
