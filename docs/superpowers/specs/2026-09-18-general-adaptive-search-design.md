# GENERAL 적응형 근거 검색 설계

## 목적

새 AI 질문 중 FAQ 또는 명시적 GitHub 저장소 분석이 아닌 질문은 `GENERAL` 경로로 처리한다. 내부 게시글의 관련성이 부족한데도 임의의 벡터 후보 한 건을 근거로 답하는 문제를 해결하고, 질문의 주제와 시점에 맞는 일회성 웹 검색을 제공한다.

## 사용자 흐름

1. `GENERAL` 질문은 기존 호환 가능한 내부 게시글 색인을 먼저 검색한다.
2. 검색 장애와 활성 색인 없음은 기존 상태로 반환한다. 이때 외부 검색으로 장애를 숨기지 않는다.
3. 후보가 있으면 질문의 모든 핵심 요구를 후보가 직접 뒷받침하는지 확인한다. 검색 순위 결합 점수는 충분성의 증거가 아니다. 모델 판정은 근거 ID를 제시해야 하며 실패하거나 형식이 잘못되면 출처 없는 답변을 내지 않는다.
4. 최근 후기 질문은 정상 내부 검색 직후 외부 후기 검색과 내부 근거 판정을 병렬로 시작한다. 웹에서 인용 가능한 후기 근거를 찾으면 시점에 관한 사실을 확인하고 외부 답변을 우선 사용한다. 웹 검색에 실패했을 때는 실제로 충분한 내부 근거가 있는 경우에만 내부 답변을 사용한다.
5. 다른 질문은 내부 근거가 충분하면 내부 답변을 사용한다. 부족하면 한 번만 웹 검색한다. 후기 질문은 후기 글을 우선하고, 공식 일정·규정 질문은 공식 원문을 우선하도록 요청한다. 일반 질문은 질문 주제와 맞는 인용 자료를 찾는다.
6. 웹 검색어는 질문에 실제로 등장한 대상, 주제, 시점으로 만든다. 질문에 없는 `크래프톤 정글` 같은 고정어를 덧붙이지 않는다. OpenAI 도구가 최종 검색어를 선택하므로 사용한 검색어를 보장하지는 않으며, 실제 인용 URL만 표시한다.

## 데이터와 오류 경계

- 기존 `JUNGLE_KNOWLEDGE` enum과 과거 행은 그대로 둔다. 신규 분류 결과만 `GENERAL`로 통일하므로 DB 마이그레이션과 과거 행 수정이 없다.
- 외부 원문·발췌·README·외부 자료를 사용한 답변은 애플리케이션 DB·FAQ·임베딩에 저장하지 않는다. 웹 검색은 `store: false`, 20초 제한, 자동 재시도 없음 정책을 유지한다.
- 내부 근거 판정 실패는 검색 장애로 처리한다. 최근 후기에서는 정상 후보 조회 직후 웹 검색이 이미 시작됐을 수 있지만, 판정 실패 시 그 결과로 장애를 숨기지 않는다. 웹 검색 실패 또는 인용 출처 부재 시 내부 근거가 충분하지 않으면 근거 부족 안내를 반환한다.
- API 키가 없는 명시적 로컬 mock embedding 데모에서는 이전처럼 후보가 있으면 mock 답변을 보여준다. 이는 실제 근거 충분성 검사가 아니며 production에서는 사용할 수 없다.
- 웹 페이지와 내부 게시글의 지시문은 데이터로만 취급한다. URL은 HTTP(S) 공개 URL만 허용한다. 블로그/공식 여부에 관한 모델 판단만으로 사이트의 권위를 확정하지 않는다.

## 검증

- 신규 일반·정글 질문 모두 `GENERAL`이며 FAQ/GitHub 경로는 그대로인지 확인한다.
- 관련 없는 벡터 후보, 일부만 답하는 후보, 충분한 후보, 최신성 요구, 검색 장애, 색인 없음에서 상태와 웹 호출 순서를 검증한다.
- 질문 속 실제 이름으로 웹 요청을 만들고 고정된 정글 검색어를 넣지 않는지 확인한다.
- 외부 인용 URL, 20초 제한, 무재시도, `store: false`, 미저장 경계를 검증한다.
- 질문 유형별 속도와 품질은 실제 로컬 API 표본 및 사용자가 검토할 평가 질문으로 별도 측정한다. 자동 테스트만으로 한국어 검색 품질을 확정하지 않는다.
