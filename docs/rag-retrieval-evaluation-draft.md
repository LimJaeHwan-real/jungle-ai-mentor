# RAG 검색 평가 질문 초안

상태: **사용자 검토 전**. 이 문서는 배포 합격 기준이나 확정 정답지가 아니다.

**근거 충분성 초안**은 현재 저장된 자료에 질문의 답이 실제로 있는지를 임시로 표시한 것이다. `충분 후보`는 답이 담긴 자료가 있어 보인다는 뜻, `부족 후보`는 자료만으로 단정하기 어렵다는 뜻, `모호 후보`는 질문을 먼저 좁혀야 한다는 뜻이다. 제목이 관련 있어 보여도 본문이 질문만 담고 있다면 `부족`으로 바꿔야 한다.

2026-09-16 로컬 개발 DB에서 읽기 전용으로 확인한 색인 문서는 64건(게시글 40건, 블로그 24건)이었다. 아래 자료 제목과 chunk 번호는 이 스냅샷의 후보이며, 다른 DB에서 같은 자료가 있다는 보장은 없다. 게시글과 개인 블로그의 경험담은 공식 입학·운영 정책의 근거로 쓰지 않는다.

| ID | 평가 질문 | 정답 자료 후보와 위치 | 근거 충분성 초안 | 검토할 점 |
| --- | --- | --- | --- | --- |
| Q01 | 핀토스 주차 전에 어떤 운영체제 개념을 미리 살펴보면 좋을까요? | 게시글 「핀토스 주차 전에 운영체제 개념을 어느 정도 봐야 하나요?」 chunk 0 | 충분 후보 | 질문·답변 전체 내용과 실제 권장 범위를 확인 |
| Q02 | 큰 프로젝트 경험이 없어도 지원서에 어떤 경험을 적을 수 있을까요? | 게시글 「지원서에 프로젝트 경험이 부족해도 괜찮을까요?」 chunk 0 | 충분 후보 | 개인 조언과 공식 선발 기준을 구분 |
| Q03 | malloc/free 문제를 디버깅할 때 어떤 순서로 확인하나요? | 게시글 「malloc/free 디버깅할 때 자주 쓰는 방법 공유합니다」 chunk 0 | 충분 후보 | 본문에 나온 절차만 정답으로 인정 |
| Q04 | 팀 프로젝트에서 Git 충돌을 줄이기 위해 정한 규칙은 무엇인가요? | 게시글 「Git 충돌을 줄이기 위해 팀에서 정한 규칙들」 chunk 0 | 충분 후보 | 해당 팀의 사례임을 답변에 표시 |
| Q05 | 정글 1주차 알고리즘 학습을 복기할 때 무엇을 기록했나요? | 게시글 「정글 1주차 알고리즘 회고: 문제 수보다 복기 밀도가 중요했습니다」 chunk 0 | 충분 후보 | 회고의 실제 항목을 확인 |
| Q06 | 입학 전에 C언어와 자료구조를 어디까지 준비했다는 사례가 있나요? | 게시글 「입학 전 C언어와 자료구조를 어디까지 준비하면 좋을까요?」 chunk 0 | 충분 후보 | 질문 글만 있다면 답변 근거로는 부족 처리 |
| Q07 | 정글 1기 수료자의 1년 뒤 경험은 어땠나요? | 블로그 「크래프톤 정글 1기 수료 후 약 1년 뒤 후기」 관련 chunk 재확인 필요 | 부분적 후보 | 개인 회고만 요약하고 일반화하지 않기; 원문 추출 노이즈 점검 |
| Q08 | 다음 기수의 공식 지원 마감일은 언제인가요? | 현재 스냅샷에 공식 일정 자료 확인 안 됨 | 부족 후보 | 공식 일정 문서가 추가되면 라벨 변경 |
| Q09 | 등록금 환불 규정은 어떻게 되나요? | 현재 스냅샷에 공식 약관 자료 확인 안 됨 | 부족 후보 | 블로그 경험담으로 정책을 단정하지 않기 |
| Q10 | 정글에 지원하면 합격 확률이 몇 퍼센트인가요? | 확인 가능한 통계 자료 없음 | 부족 후보 | 숫자 추정이나 임의 계산을 답변하지 않기 |
| Q11 | 정글 준비는 무엇부터 해야 하나요? | 입학 준비·학습 후기 게시글 여러 건 | 모호 후보 | 질문 구체화 또는 출처가 다른 조언들을 구분 |

검토 요청: 각 질문의 표현, 정답 자료·chunk, 충분/부족/모호 라벨을 확인해 주세요. 특히 Q06은 질문 글만으로 답변이 가능한지, Q07은 블로그 본문 추출 품질이 충분한지 확인이 필요하다. 라벨 확정 후 동일 데이터에서 기존 검색과 개선 검색의 Recall@k·MRR·근거 정확도를 비교하고 합격 기준을 정한다.
